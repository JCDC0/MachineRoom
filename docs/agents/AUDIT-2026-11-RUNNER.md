## Severity

- High: work is lost, two agents can edit one worktree, or a merge can land on a branch it did not check.
- Medium: a run, queue or record reports the wrong outcome, or leaves the project, a lock or a worktree in a state the owner has to repair.
- Low: an edge case, a misleading error or stale state with no lasting harm.

## The OpenCode start failure on 2026-11-03

The runner cannot retry safely today and does not report the case well. It can report it better with the data it already has. `startLane` has the log, the exit code, the minutes and the harness descriptor, but it prints only `start failed` for a spawn error, then the exit code and a summary built from the log. `harnessByKey[harness].failure(log)` exists for OpenCode and is used by `server/orchestrator.js`, not by `run-lane`. The record has no `startFailed` field. So the first-second failure becomes a normal failed run with `exitCode: 1`, `minutes: 0.0`, zero tool calls and a detached branch.

A retry is safe only for the narrow case where no tool call was parsed, no commit was made, the run lasted under a minute and the log matches the readiness sentence. In that case one retry after a short pause is reasonable, because the harness never reached the work. A blind retry is not: the harness may have started a server or written a file before it failed, and two identities on one worktree are worse than one failed run. The fix in finding 9 prints the failure sentence and marks the record even when no retry is made. Two other lanes starting beside it make a port or resource clash plausible, so the retry should also mention that it is retrying and should not be attempted when another lane on the same harness is starting in the same second.

## Checked and found sound

- `git switch -- <branch>` works on this git. A temp repo switched to `other` and reported `Already on 'main'` for the current branch. The `--` is not a bug.
- `unlinkSync` of a Windows junction works on this Node (v24). `review-lane`'s `removeLink` is not broken; the `rmdirSync` fallback in `worktrees.mjs` is redundant but harmless.
- Project folders and worktree paths with spaces are passed as argv, not through a shell, in every git and spawn call in the named files. I found no space-related break for a folder. The two name breaks are the lane key used in a branch and the `--stop` character check (finding 13).
- A failed task, a killed task and a failed test do not commit in `runQueue`; the existing queue tests cover those three. The fault is the record after a test failure (finding 7), not a commit.
- `worktreePlan` refuses a dirty worktree, and `--clean` refuses tracked or untracked changes. The ignored-file case (finding 2) is the gap.
- `review-lane` builds its merge in `MachineRoom-review-*` beside the checkout, never merges into either checkout and removes the temp tree unless `--keep`. I found no path that touches the lane or main checkout.
- `server/git.js` already refuses a switch without a page Origin, a switch while a turn or a lane run is open, a dirty checkout and a branch held by another worktree.
- `outcome` keeps the newest outcome per branch in `server/outcomes.js:3-13`, so recording the same branch twice does not inflate the merge rate.
- `takeLaneLock` removes a stale holder and a half-written takeover with a retry; I did not find a lock left behind on the normal path. The gap is the stop path (finding 3).
- `childEnvironment` keeps only the allow-list and the harness key names, so a lane does not inherit the owner's other keys.
