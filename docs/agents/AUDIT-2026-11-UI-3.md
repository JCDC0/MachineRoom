# UI audit 3

P547. Source review for 1280x800 and wider. No screen check was available. Layout findings below follow the CSS and need a check by eye.
The settled modes, composer status, Agent messages toggle, footer agents list, rails, run-end rows, Teams fold and tunnel, star and bracket colours are excluded.

## UI3-1 | P1 confusing | Waiting looks finished

`src/styles.css:6528`, `src/ui/orchestratorChat.js:191`, `src/ui/OrchestratorChat.jsx:1397`.
The chat tabs give waiting orchestrators a green dot. Idle also falls through to that same green dot. Green means finished work elsewhere in the room, so resting and waiting look like success.
Fix: merge the tab dots into the room's state colours, with waiting yellow and idle dim white, and remove the green waiting rule.

## UI3-2 | P2 cluttered | Attention comes after the start tools

`src/ui/panels/DispatchPanel.jsx:1073`, `src/ui/panels/DispatchPanel.jsx:1577`, `src/ui/panels/DispatchPanel.jsx:1833`.
Dispatch puts the project run form, the brief tools and all running rows before Needs you. At 800 pixels high, an owner looking for a failure must scroll past tools for starting more work.
Fix: move the existing Needs you block before the project run form, keeping one copy.

## UI3-3 | P2 cluttered | Two orchestrator switches

`src/ui/Hud.jsx:645`, `src/ui/Hud.jsx:658`, `src/ui/OrchestratorChat.jsx:1384`.
The menu band lists Main and each sub. The inline chat repeats them as tabs, with another active marker for the same conversation.
Fix: make the menu band a plain conversation title and keep the chat tabs, including Team, as the conversation switch.

## UI3-4 | P2 cluttered | Projects starts with branch tools

`src/ui/Sidebar.jsx:830`, `src/ui/RepositoryPanel.jsx:231`, `src/ui/RepositoryPanel.jsx:281`.
Opening Projects shows Repository, a branch filter, branch rows and New branch before the Projects heading and project list. The branch list alone can take 192 pixels (`src/styles.css:7838`).
Fix: move RepositoryPanel below the current and recent project rows.

## UI3-5 | P2 cluttered | Small targets use many sizes

`src/styles.css:780`, `src/styles.css:1972`, `src/styles.css:7395`, `src/styles.css:8687`, `src/styles.css:9781`, `src/styles.css:9800`, `src/styles.css:10751`.
Clear in the failure tray is 16 pixels high, the clickable Reviews count is 16, conversation menus are 22 square, agent switches are 12 high, Add and Chat are 18 square, and lane selection boxes are 12 square. These are separate hit targets, not just small icons inside larger buttons.
Fix: remove the small target overrides and merge these controls into one shared minimum 24 pixel hit area, keeping their existing icons and actions.

## UI3-6 | P2 cluttered | Pin repeats inside every row

`src/ui/Sidebar.jsx:669`, `src/ui/Sidebar.jsx:694`, `src/ui/sidebar.js:240`.
Each conversation has a pin button and a Pin or Unpin menu item. Both call the same row action. The extra icon takes space from the title in the narrow sidebar.
Fix: remove the row's pin button and keep Pin or Unpin in the existing menu, with Pinned still identifying the group.

## UI3-7 | P2 cluttered | A long address can clip the dock actions

`src/ui/AgentDock.jsx:108`, `src/styles.css:1507`, `src/styles.css:8105`, `src/styles.css:8204`.
The right column stays 280 pixels wide, with 12 pixel side padding. Focus, Log and Open followed by a full address share one flex row without wrapping. A long hostname cannot shrink to fit, and the column hides the overflow, so the address action can be cut off.
Fix: shorten that button to Open address and keep the full address in its title.

## UI3-8 | P2 cluttered | Chat adds seven extra colours

`src/ui/orchestratorChat.js:256`, `src/ui/orchestratorChat.js:265`, `src/ui/OrchestratorChat.jsx:1461`, `src/ui/OrchestratorChat.jsx:1501`, `src/ui/LaneConversation.jsx:179`.
Lane names, agent messages and lane conversation content use orange, pink, purple and other colours from AGENT_PALETTE or a lane's own colour. These are shown text colours outside the HUD palette, separate from the excluded room stars and brackets.
Fix: remove the sender colour overrides and palette fallback from HUD text, keeping names in white and the existing state classes for outcomes.

## UI3-9 | P3 polish | Console has its own cyan

`src/styles.css:7`, `src/styles.css:11215`, `src/styles.css:11221`, `src/styles.css:11230`.
The command console uses #38e8ff for text, border and glow. This is an extra colour beyond the allowed blue #2a9dff, and a local shell command gains another bright accent.
Fix: merge the console text and border into the white activity style and remove its cyan glow and tinted fill.

## UI3-10 | P3 polish | Fork and Branch name the same action

`src/ui/sidebar.js:255`, `src/ui/Sidebar.jsx:447`, `src/ui/OrchestratorChat.jsx:850`, `src/ui/OrchestratorChat.jsx:1314`.
The conversation menu says Fork while message actions say Branch. Both create a conversation through branchOrchestratorSession, with a different message cutoff.
Fix: merge the wording under Branch, including the menu's empty-conversation message, and remove Fork from shown copy.

## UI3-11 | P1 confusing | Runner warning opens empty details

`src/ui/healthNotice.js:35`, `src/ui/Hud.jsx:836`, `src/ui/Hud.jsx:844`.
When the health answer is otherwise OK and runner.alive is false, The runner looks stopped is clickable but its lines array is empty. Opening it shows only Close. The owner gets no next step.
Fix: merge the warning and a short runner restart instruction into the notice text, and remove the empty details popup for this state.

The scanned font declarations use Jost or Space Mono through the shared variables, with weights 400 or 500. No fixed em dash copy or bold declaration was found in the UI source scan. Project and conversation titles in the menu have ellipsis rules, model search and sort controls are 24 pixels high, and chat tabs can wrap. These checks are from source, not rendered measurements.

Checked and fine
