# Security review of the change since the audits, October 2026

Written 2026-10-22 by the cloud session on the branch `claude/security-delta-q1`, from 0.1.152 (`421b4b6`), for brief Q1. It reads what went into `server/`, `src/` and `scripts/` from the UI audit's merge (0.1.121, `66d6376`) to 0.1.152: 49 files, 4770 lines added and 362 removed (`git diff --stat 66d6376 421b4b6 -- server src scripts`). It also reads two files the brief named that did not change in that span: `server/policy.js` and `scripts/hand-run.mjs`. It was read as an attacker who can shape what reaches the bridge and the page (agent output, a planner's reply, Paperclip data, file names), and as a careful reviewer. This is a report only. No code changed. File and line numbers are those of `421b4b6`.

The two audits are `AUDIT-2026-10.md` (the bridge and the pure logic) and `AUDIT-2026-10-UI.md` (the code in the browser). This review does not repeat their findings. Where a change since then closed one of their open items, the section "What was checked and found sound" says so.

## Severity

The scale of the two audits, joined:

- High: code from an unreviewed lane branch runs as the owner, a write, a paid run, a merge or a backup starts without the owner choosing it, or a key can leave the machine without anyone choosing it.
- Medium: a review can be misled, the owner confirms one thing and another is written or run, a confirm step can be skipped, a key that the bridge masked before now reaches the page, the bridge stops or hangs, or a number that feeds the routing policy is wrong.
- Low: wrong output on odd input, extra work or bytes, or slow growth in a long session, with no lasting harm.

## What was checked and found sound

- The plan accept route (`server/plans.js`). It needs `confirmed: true` and 1 to 8 string ids, answers 404 when the bridge has no briefs folder, and writes `TASKS.md` through a temporary file and a rename. The ids come only from the plan it parsed, through `Object.hasOwn` on null-prototype tables. Ids already in `TASKS.md` are refused, because the route reads `TASKS.md` again after Paperclip answers. Two accept calls at once almost always see each other: the second reads `TASKS.md` after the first wrote it and answers 400 for the taken ids. They can both read the old file only when both Paperclip answers finish in the same event loop turn, since a few awaits lie between a call's read and its write; the later write then drops the earlier call's briefs. The Plan tab sends one call at a time, so this needs two pages or a script. `briefMarkdown` folds every whitespace run, line breaks included, to one space, so a brief stays on one line, and `parseBriefs` splits only on line breaks. A planner comment is read only from an agent whose Paperclip role is `pm`.
- The live-runs route and its notice (`server/control.js`). The route only reads, encodes the company id, has the 15 second limit and the `tasks` feature gate, and maps each field to text or `null`, so a run with an object in a field, a `null` entry or a list that is not a list gives no error. `changeEvents` adds `liveRuns` only on run-queued and run-status frames, never on log frames, and the page batches notices over 100 ms.
- The folder-shaped tree and `packTree` (`server/index.js`). `packTree` falls back to plain paths for a list it cannot pack (a name that is not text, a path that does not rebuild), and `readFileList` in `src/live/tree.js` accepts a parent only when it comes before its child, so a bad list cannot loop or point outside the table. Every name reaches the page as text. `git ls-files -z` keeps line breaks in names inside one entry.
- The tree read that no longer blocks. `startTreeRead` keeps one read in flight, and a change during a read sets `treeDirty` for exactly one more read. `GET /api/tree` shares the read in flight, so a page that asks many times starts at most one git. git runs by its absolute path with a 20 second limit and `GIT_CEILING_DIRECTORIES`. `stop()` during a read publishes nothing. This closes N14 of the first audit.
- `createSplitMasker` and its wiring, for the cases the brief named. A frame is never sent twice: each one leaves the queue once, from its head. Order holds, because a held frame keeps every later frame behind it. A run that never ends still releases within 1 second through the timer, and each stream keeps at most 4096 characters of open line. At most 256 streams are kept, and an old stream that holds nothing is dropped first. `stop()` drops the frames it holds, so they never reach a page or the history; those are at most 1 second of frames from a bridge that is closing. The Paperclip socket opening again leaves held frames to the timer, which is sound for order but not for masking (D4). The proxy route still masks nothing, as Known limits says.
- The policy route (`server/policy.js`). It reads `policy.json` from the bridge's own briefs folder, parses the body as JSON, so a `__proto__` key stays a plain property, checks `failures`, and reads Paperclip's costs and quota windows only, with a time limit. A Paperclip that does not answer falls back to `Quota and spend were not read.`.
- The Route row and the Plan tab (`src/ui/panels/`). `Use` only fills the form, and the task is created only by the form's own button. Every route reason, problem and brief field reaches the DOM as React text, and lane names are read with `Object.hasOwn`. `PanelBoundary` (U7) keeps a panel that throws from unmounting the room; this closes N2 of the UI audit for the drawer. `mergeHead` (U6a) and the head in the diff answer (U6) close N1 of the UI audit.
- The cost board (`src/engine/board.js`) and the task line in the callout (`src/model/liveTasks.js`, `src/engine/agents.js`). Both set `textContent` only. Names, quota labels and errors pass through `visibleText`, and the share bar width is clamped to 0 to 100 percent. Money and token counts that are not finite numbers show as `$0.00` and `?`. The task line takes the identifier, a name or the title, cut to 16 characters after `visibleText`. `nameLabel` cuts an agent's name to 32 characters, which closes N4 of the UI audit.
- `scripts/hand-run.mjs`. It starts git by its absolute path in the lane's worktree with `refs/heads/main`, refuses a lane with a command line, a brief that `briefProblems` refuses, the branch `main` and a branch that has a record, and writes one JSON line. The branch text goes into `runs.jsonl` as JSON data, never into a command line.
- `scripts/fake-paperclip.mjs` listens on `127.0.0.1` unless told otherwise and reads `public/fixtures` unless given another folder.
- `src/model/folderView.js`, `src/engine/cards.js`, `src/model/paths.js` and `src/live/simulated.js`. Card names and rows go through `visibleText` (U10, which closes N5 of the UI audit for the room). `simulatedSpeed` clamps the speed (N7 of the UI audit).
