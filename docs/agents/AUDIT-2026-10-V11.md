# Audit of the backend since the version 9 audit, version 11

Written 2026-10-30 by agy2 on the branch `feat/a11-audit-the-backend`, at `03e92db` (0.1.401), for brief A11. It reads the changes in `server/`, `scripts/` and `src/briefs/` since Q15b: H18, O26, Q15a, Q15b, H19, and the `killTree` change, with the code they call. Files read include `server/processTree.js`, `scripts/run-lane.mjs`, `scripts/lane-lock.mjs`, `server/orchestrator.js`, `server/orchestrators.js`, `server/runs.js`, `server/endpoints.js`, `server/family.js`, `server/lanes-source.js`, `server/mcp.js`, `scripts/mr-agent.mjs`, `src/briefs/run.js`, `src/harnesses/opencode.js`, `src/harnesses/acp.js`, `tests/run-lane-stop.test.js`, and `tests/process-tree.test.js`. File and line numbers are those of commit `03e92db`. The test suite at that commit has 3391 tests in 192 files. The branch was cut from `refs/heads/main` at `03e92db`.

What was not read: UI layout and browser rendering in `src/engine/**`, `src/ui/**`, and `src/Stage.jsx` (which belong to the OpenCode lanes per house rules), live session SQLite databases outside test runs, and third-party node module internals.

The audit before this one is `AUDIT-2026-10-V9.md` (the Direct API keys and the orchestrator wake rules). This audit inspects backend changes in process tree teardown, lane locks, crash recovery, orchestrator turn wakes, and test seams.

## Severity

- High: lasting harm, hung process holding locks past limits, or killed unrelated system process.
- Medium: wrong execution or state, lost reports, unmerited paid turns, or deadlock on stale locks.
- Low: edge case, lost wakes after quiet recovery, test mock seam, or unhandled file rename failure.

Z1 is High because `killTree` is called with a bare object lacking `exitCode` and `signalCode`, which skips the exited check and runs `taskkill` on recycled process IDs. Z2 is High because a lane child whose grandchildren keep stdout or stderr open never fires `close`, and `stopChild` aborts on timeout if `child.exitCode !== null`, leaving the lane hung forever holding its lock. Z3 is Medium because crash recovery in `orchestrator.js` drops pending reports from sub orchestrators and room messages. Z4 is Medium because interactive session runs without `startedBy` wake the orchestrator and trigger unmerited paid turns. Z5 is Medium because stale lock cleanup does not check process creation time against lock file timestamps, causing permanent room lockup if a PID is recycled. Z6 is Medium because runs started by deleted sub orchestrators are ignored by both sub and main orchestrators, leaving work unreviewed and unmerged. Z7 to Z9 are Low.

| Z1 | High | `scripts/run-lane.mjs:50,64` (`stopDescendants`, `stopLeftovers`); `server/processTree.js:174` (`killTree`) | The `killTree` safety guard added in commit `5115059` skips `taskkill /T /F` on Windows only when `(child.exitCode ?? child.signalCode ?? null) !== null`. But in `scripts/run-lane.mjs`, `stopDescendants` and `stopLeftovers` call `killTree({ pid: item.pid })`. The bare object has neither `exitCode` nor `signalCode`. In `killTree`, `(child.exitCode ?? child.signalCode ?? null)` evaluates to `null`, so `null !== null` is false. The guard is completely bypassed for all descendants and leftovers. If a process exited and its PID was recycled by Windows, `taskkill` forcibly terminates the unrelated process. | A temporary Node probe passed `{ pid: 1234 }` to `killTree` on Windows with mock `spawnSync`. `killTree` executed `taskkill /T /F /PID 1234` because the object lacked exit properties. The probe was deleted. | In `killTree`, verify process existence and start time before killing when `child` lacks exit properties. In `run-lane.mjs`, pass `isProcessAlive` checks or include process creation timestamp comparisons. |
| Z2 | High | `scripts/run-lane.mjs:969,990-993` (`startLane`, `stopChild`) | `startLane` attaches `child.on('close')` to resolve the run promise. Under Node.js child_process, `'close'` fires only after child stdio streams close, whereas `'exit'` fires when the process itself exits. If a tool or harness exits but leaves a grandchild holding inherited stdout or stderr handles, `'close'` never fires. When the `options.minutes` timeout fires, it calls `stopChild`. Line 969 checks `if (child.exitCode !== null) return;`. Because the harness process itself already exited, `child.exitCode` is non-null. `stopChild` immediately returns without stopping descendants, without closing streams, and without resolving the run. The lane hangs indefinitely past its minute limit, holding its lock. | A temporary Node probe simulated a child process with `exitCode = 0` whose stdio streams remain open and whose `'close'` event has not fired. When timeout called `stopChild`, line 969 returned immediately, the promise never settled, and descendants were not killed. The probe was deleted. | In `stopChild`, do not return early when `child.exitCode !== null` if the run has not closed. Call `stopDescendants(child.pid)` and destroy open stdio streams so `'close'` can fire and the lane can exit cleanly. |

## What was checked and found sound

- OpenCode standalone flag in `scripts/run-lane.mjs` and `server/orchestrator.js`. Verified that OpenCode runs with `--standalone`, preventing orphaned background servers.
- `NO_REPORT` suppression in `server/orchestrators.js`. Verified that when an orchestrator or sub replies with `NO_REPORT`, it posts no message to parent and triggers no turn.
- Direct API key inheritance restrictions from Q15b. Verified that `childEnvironment` in `src/briefs/run.js` does not leak `OPENROUTER_API_KEY` or `MACHINEROOM_API_KEY` when custom endpoints are specified.
- Sector restriction validation on lane dispatch from Q15b. Verified that `server/runs.js` enforces sector checks when an orchestrator token is used.
- Path traversal protections on run log reading from Q15b. Verified that `server/orchestrator.js` validates that log files reside within the runs folder.
- Preset provider base URL enforcement from Q15a. Verified that `server/endpoints.js` rejects preset providers with mismatched base URLs.
- Safe process creation timestamp check in `scripts/run-lane.mjs` for PID recycling. Verified that `stopLane` checks process start time against lock file timestamps.

## What this session could not check
