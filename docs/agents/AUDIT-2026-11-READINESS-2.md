Read on 2026-11-13 at `478caf7c`, version 0.1.401. This follows P164 beyond the first merged change. No application code changed. Only synthetic data was used for probes. No subscription, real run, owner conversation or credential was opened.

**Probe** means assertions against the current functions with synthetic inputs. **Read** means the code path was inspected. Resource exhaustion and elapsed days are not measured unless a row says otherwise. Rows are ordered by harm, with direct data loss first.

## Paths checked and existing IDs

- **Long-open page.** The live log holds 200 entries (`src/model/log.js:5`). Logger labels cap at 2,000. The pipeline caps seen IDs at 20,000 and ended runs at 1,000, and sweeps idle parser state after 30 minutes of feed time (`src/model/pipeline.js:28`). The recorder compacts consumed slots after 1,024 (`src/model/sessionRecorder.js:9`), so an ordinary time-ordered feed does not retain every frame since page load. D8 is its separate burst limit.
- **Listeners and frame rate.** The inspected Stage effects clear timers and subscriptions. The live effect closes its stream on cleanup (`src/Stage.jsx:1280`). Room disposal cancels animation, clears timers, disconnects ResizeObserver, removes listeners and disposes renderer resources (`src/engine/room.js:1314`). The room still draws each animation frame while mounted (`src/engine/room.js:1041`). No hours-long browser run or frame-rate measurement was made. Existing large-room performance findings stay under **LIMITS P19 and P26**. Existing slow-frame and hidden-tab clock behavior stays under **LIMITS P27**.
- **Bridge lifetime.** Stop clears the heartbeat, project watcher, lane and session polling, and closes clients (`server/index.js:1499`). Tree client membership uses weak collections (`server/index.js:739`). The source timers are fixed per source, not one new timer per completed run. OpenCode drops finished session state after one hour and caps forgotten entries at 200 (`server/opencode-sessions.js:484`), but retains metadata for database rows still present. Claude's faulty eviction behavior is D6. Neither reader rotates the harness's own session files.
- **Restart during a lane.** A normal bridge stop calls `runs.stopAll`, which kills its runner process trees and clears the in-memory running map (`server/runs.js:736`). It does not wait for a durable terminal record. A forced process-tree stop can prevent the runner reaching its final append (`scripts/run-lane.mjs:1668`). A new bridge does not restore that map from locks. The lane source can rediscover recent or growing logs; after ten quiet minutes it checks the lane lock and can emit `failed: no record` (`server/lanes-source.js:746`). Startup logs older than one minute wait for growth. Worktree changes remain for inspection. Queue recovery and remaining-task handoff stay under **P164 suggested feature 3**, not a second feature row here. No real runner was killed in this audit.
- **Restart during chat or merge.** Chat persistence uses a temporary file and rename, reports save errors, and restores a working conversation to idle with a resend notice (`server/orchestrator.js:1141`, `server/orchestrator.js:1227`, `server/orchestrator.js:1336`). It does not blindly replay the interrupted owner turn. Its recovery record has D2. Merge requests have a two-minute git timeout and inspect the checkout after a timeout; the merge-commit path attempts abort (`server/reviews.js:502`, `server/reviews.js:587`). These handlers cannot finish their recovery after their own process is gone. A hard crash can require inspecting git status, HEAD and merge state before retrying. No crash, power loss or real merge was induced.
- **Sleep.** Lane limits use `setTimeout` (`scripts/run-lane.mjs:1494`); chat has a one-hour turn timer (`server/orchestrator.js:1875`). There is no explicit machine-sleep checkpoint in these paths. Timer and child-process behavior across actual Windows sleep was not tested. Missed stream activity after a disconnect is D4. Existing process-tree and stale-lock safeguards stay under **LIMITS H19, Q16b and H20**.
- **Two rooms on one project.** Two tabs on one bridge share the orchestrator, dispatch map and git write lock. Each page has its own renderer and recorder. Two lane-enabled bridges using the same project path and runs folder are refused by the per-project chat lock (`server/orchestrator.js:571`, `server/orchestrator.js:2759`); this is not two independent chats writing the same file. Different project paths or different runs folders produce different locks. The git write guard itself is process-local (`server/git.js:128`), so do not treat it as a cross-process transaction lock. Duplicate live dispatch and merge were not exercised.
- **P164 findings.** **R1** is already addressed in this snapshot by destination branch and head validation (`server/reviews.js:346`, `server/reviews.js:678`). **Q4** is addressed by the fast-forward strategy and its distinct confirm UI (`server/reviews.js:401`, `src/ui/panels/ReviewsPanel.jsx:20`). Those parts of P164 no longer describe current code. **R2** still owns check-gated Merge; **Q2** still owns matching review results to the project. D2 concerns creation of a wrong recovery record, a different path from Q2's review lookup. No new row repeats those merge findings.

## What remains to clean by hand

The owner must inspect and choose which completed run logs, sidecars, outcomes and recordings to archive. Removing a recording's index entry does not reclaim its three files. Chat JSON files are bounded within each project and orchestrator, but files for abandoned projects and removed subs are not removed by the recent-project pruning. That pruning only updates the recent list (`server/projects.js:294`). Corrupt chat files can remain as `.bad` backups.

Lane worktrees are reused, not removed after a merge. The existing worktree command removes only clean, merged, non-running, unlocked worktrees, and refuses ignored files other than `node_modules` (`scripts/worktrees.mjs:157`, `scripts/worktrees.mjs:300`). Dirty work, commits not merged, real dependency folders, retained branches, harness session history and crash leftovers need inspection. No cleanup was performed and no owner's data was moved or deleted.
