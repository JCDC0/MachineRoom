The 200,000-path probe measured 159 ms for the first folder response, 16 ms for an immediate cached response and 22 ms for each of two later responses. The synthetic list read took 48 ms cold and 6 ms warm. These are in-memory lower bounds, not disk benchmarks: the real git reader also runs `git ls-files` and the deleted-file check, while a plain project walks directories. The page discovers the tree on connection and then follows SSE, so an idle connected page does not itself generate these repeated GETs.

Other compatibility checks: `npm run check`, `node --test "tests/a b.test.js"` and a quoted executable path with spaces split correctly. Quoted paths containing `&`, and quoted JavaScript containing `;`, are refused by the character check even though those characters could be literal arguments. This is the documented conservative refusal; an npm script remains the workaround. No normal Windows archive refusal or repeating retry in an idle, healthy room was reproduced.
