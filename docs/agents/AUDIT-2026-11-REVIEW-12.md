## The orchestrator's corrections

- Finding 2 is half right, and not a push blocker. The bridge starts git with `GIT_CEILING_DIRECTORIES` set to the project's parent, so a project that is a folder inside a larger repository finds no repository: its list fails and the bridge walks the disk, which never shows a deleted file. A test through `readTreePartial` on such a folder answers null for that reason. `--relative` is still right for the day the ceiling changes, so it went in with finding 3 (`64c41251`), with a test that runs the command in a subfolder.

Timed by hand at 40,000 files: 175 ms, against 161 ms for `git diff` and 1408 ms for `git ls-files --deleted`. A test checks that a read after a time-only change leaves `.git/index` as it was.

- Findings 1, 4, 5 and 7 hold as written and are not push blockers. They go to brief P70.
- Finding 6 holds, and `git diff-files` honours assume-unchanged as `git diff` does (checked by hand: it names nothing where `git ls-files --deleted` names the file). A file marked assume-unchanged is one the owner told git not to look at; the room shows it until the next commit. Left as it is.
