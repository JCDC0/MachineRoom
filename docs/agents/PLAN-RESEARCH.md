Drafted by Argon (Gemini 4 Argon High) on 2026-11-16 from the three independent P442 surveys:
- `docs/agents/research/HARNESS-SURVEY-CLAUDE.md` (P442a, Claude Opus 5.5 High)

## 1. What Users Want: Where All Three Surveys Agree

All three surveys converged on eight core user demands across public surveys, GitHub issue trackers, Hacker News discussions and tool documentation:

1. **Fast, trustworthy verification of diffs is the primary bottleneck, not generating code** (`Claude: Trust and review`, `Sol: T1`, `Argon: Theme 3`).
   - All three cite the 2025 and 2026 Stack Overflow Developer Surveys (46% distrust AI accuracy, 66% cite "almost right" patches as the top frustration, and 48.0% of 14,304 respondents in 2026 grant only conditional trust when output is easy to verify), backed by DORA 2025 (higher throughput lowers delivery stability without verification gates) and METR's July 2025 trial (experienced open-source developers took 19% longer).
   - Users want bounded diffs, runner-verified test and build results tied to the exact branch head, files grouped by risk or scope, and a clear split between what the agent claimed and what the runner checked.
2. **Transparent cost, quota windows, cache behavior and route changes** (`Claude: Cost and quota`, `Sol: T2`, `Argon: Theme 1`).
   - Rate-limit surprises and opaque token drain are the top single-tool operational complaints (Claude Code issues `#29579`, `#41583`, `#41788`, `#54750`, `#105621`; Gemini CLI `#17006`; community monitors like `ccusage`).
   - Users want per-change cost and token attribution across retries and failovers, prompt-cache hit visibility, clear notice of missing provider cost data, and the exact reason a route was skipped or failed over.
3. **Useful autonomy inside boundaries that match the visible setting** (`Claude: Trust / Item 11`, `Sol: T3`, `Argon: Theme 2`).
   - Developers reject constant yes/no approval prompts that cause permission fatigue and push users into unsafe full-bypass flags (Stack Overflow May 2026 pulse survey: 60% block unapproved system changes).
   - They want OS sandboxes or enforced workspace rules, and they require parent permission modes to hold inside child subagents, ACP wrappers and resumed sessions without silent privilege escalation or unseen hangs (OpenCode `#43888` and `#56907`, Codex `#40125` and `#51056`).
4. **Distinct controls for steering, queueing, pausing and interrupting a running agent** (`Claude: Steering a running agent`, `Sol: T7`, `Argon: Theme 9`).
   - Users distinguish steering at the next safe tool boundary, queueing a follow-up for the turn end, pausing before the next model call, and stopping immediately (Claude Code `#30492`, `#64624`, `#65827`; Antigravity CLI `#249`; Codex 0.159 turn steer; Kiro; Pi).
   - They also want visible delivery state so they know whether a sent message is waiting in an inbox or has been read by the agent.
5. **Worktree isolation without repetitive environment setup chores** (`Claude: Parallel orchestrators`, `Sol: T5`, `Argon: Theme 4`).
   - Git worktrees prevent concurrent file overwrites, but users complain about slow initial checkout creation, missing untracked `.env` files, port collisions across local dev servers, and uncertainty about when a worktree holds unreviewed work (Conductor HN `#44594584`, Cursor worktree setup docs, Paradev).
6. **Preserved task constraints and inspectable original history across compaction** (`Claude: Context and instructions`, `Sol: T6`, `Argon: Theme 5`).
   - Users report "compaction amnesia" when auto-compaction drops constraints, column names or prior failed attempts, and they object when compaction hides the original transcript and file list from human review (Claude Code `#27242`, `#64619`, `#102361`). Static repo instructions in `AGENTS.md` also cut runtime and tokens (`arXiv:2510.21413`, `arXiv:2602.14690`).
7. **Checkpoints and recovery that keep code and chat in sync without losing human work** (`Claude: Item 10`, `Sol: T11`, `Argon: Theme 10`).
   - Users ask for pre-turn checkpoints and rewind, and they complain when undo reverts code without chat state (Claude Code `#29521`), when restoring a checkpoint overwrites intervening human commits (Cline `#13550`), or when an agent loops on the same failing tool call (Claude Code `#103414`).
8. **Low-friction beginner setup that verifies real readiness and starts in Plan mode** (`Claude: Setup for a beginner`, `Sol: T10`, `Argon: Theme 7`).
   - First-run failures cluster around auth tokens that pass `--version` or login but fail on the first turn (Claude Code `#28176`, `#83633`), broken Windows sandbox setup (Codex `#56532`), and overwhelming multi-agent UI before a user completes one safe Plan-first task.

## 2. Where the Three Surveys Disagree and Why

1. **How many parallel agents users want by default (`Claude: Few bounded agents`, `Sol: T4`, vs `Argon: Theme 4`).**
   - *Where they differ:* Sol cites the May 2026 Stack Overflow pulse survey showing 68% of developers prefer predictable single-agent workflows, and Claude cites practitioner reports that 2 to 3 bounded agents under one human is the ceiling before review and state collisions dominate (proposing a soft cap of 3 in Claude #7). Argon emphasizes power-user "coder to conductor" workflows running 3 to 8 worktree agents in Cursor 2.0, Claude Squad and Vibe Kanban (proposing per-lane port offsets and env copy in Argon #1).
   - *Why:* Sol and Claude weighted broad developer surveys and general HN threads where human review bandwidth is the limit, whereas Argon sampled issue trackers and changelogs of multi-agent orchestrators whose self-selected users already run parallel fleets.
   - *Resolution in this plan:* Keep parallel worktrees optional, add pre-dispatch file overlap warnings and a soft advisory warning above 3 concurrent lanes (Item 3), and add reusable worktree setup and port env support for users who do run parallel lanes (Item 9).
2. **Immediate one-click Rewind buttons vs safeguarding intervening human work first (`Claude #10` and `Argon #5` vs `Sol #14`).**
   - *Where they differ:* Claude (#10) and Argon (#5) propose recording a hidden ref or HEAD SHA before each turn and offering a one-click Rewind button in Reviews or conversation. Sol (#14, T11) warns against adding rewind buttons until recovery proves it cannot overwrite intervening human commits or dirty files, citing Cline `#13550`.
   - *Why:* Claude and Argon focused on feature requests for Claude Code `/rewind`, while Sol traced post-launch data-loss bugs in Cline's checkpoint tracker.
   - *Resolution in this plan:* Record checkpoint refs before lane continuations and turns now, but gate any rewind route on a clean worktree and zero intervening non-lane commits, with an explicit preview of affected commits and files (Item 8).
3. **One-click ACP agent onboarding vs fixing ACP auto-approval first (`Claude #9` vs `Sol #1` and `Argon #10`).**
   - *Where they differ:* Claude (#9) recommends listing ACP registry agents in Settings so users can add any of the 25 to 30+ ACP agents as a lane in one step. Sol (#1) and Argon (#10) inspected `scripts/acp-run.mjs:184-195` (`answerRequest`) and found that MachineRoom currently selects `allow_always` before `allow_once` on every `session/request_permission` request and lists no modes for `acp` in `src/control/modes.js`.
   - *Why:* Claude looked at external ACP ecosystem adoption, while Sol and Argon audited MachineRoom's local ACP runner against its permission contract.
   - *Resolution in this plan:* Enforce lane permission modes in `scripts/acp-run.mjs` and display each harness's sandbox level in the Inspector first (Item 1), before adding one-click ACP registry onboarding.
4. **How to fix context loss: `AGENTS.md` defaults vs searchable logs with compaction links vs injected state blocks and repo maps (`Claude #8` vs `Sol #7` vs `Argon #6, #7`).**
   - *Where they differ:* Claude (#8) prioritizes automatic `AGENTS.md` inclusion and `doctor` warnings; Sol (#7) prioritizes keeping the uncompacted transcript searchable with source links from each compaction summary; Argon (#6, #7) prioritizes re-injecting a structured JSON state block across autocompact and building a 4,000-character symbol map for `mr-agent`.
   - *Why:* Each researcher targeted a different layer: initial project onboarding (Claude), human auditability after compaction (Sol), and model state retention across compaction or search turns (Argon).
   - *Resolution in this plan:* Combine archived pre-compaction turns with a preserved structured state block in `server/orchestrator.js` (Item 10), and fold `AGENTS.md` checks into `doctor` and prompt building (Item 11). Leave the `mr-agent` symbol map as an optional native-harness follow-up.
5. **Quota and cost telemetry: exact-looking local 5-hour block bars vs provenance and partial-total honesty (`Argon #3, #14` vs `Sol #8` and `Claude #2`).**
   - *Where they differ:* Argon (#14) proposes estimating Claude Code's 5-hour billing blocks from local `~/.claude/projects/` timestamps (`ccusage` style). Sol (#8, T2) shows from Claude Code `#54750` and Gemini CLI `#17006` that local token logs frequently diverge from provider-enforced subscription windows and cannot be converted reliably into dollars, so the UI must stress provenance, observation time, missing providers and fallback reasons.
   - *Why:* Argon drew on community token calculators, while Sol drew on bug reports where local usage percentages conflicted with provider blocks.
   - *Resolution in this plan:* Sum cost, tokens and minutes across all attempts of a branch in Reviews (Item 2), and add cache-token breakdown, wasted-spend tracking, missing-cost labels, quota observation/reset times and skip reasons to the Cost Board (Item 7), without claiming local Claude token sums equal Anthropic's server-side billing block.

## 3. Baseline Note: What Is Already on `main` or Briefed in P438 to P441

Several survey recommendations overlap with existing code or briefs already in `docs/agents/TASKS.md`:
- **Review check badges (`Argon #9`):** `server/reviews.js:437` (`checkStateFor`) and `src/ui/panels/reviews.js:8` (`formatChecks`) already join `record.tests` (`passed`, `failed`, `unchecked`) for the current `head` and format `lastRun` (`minutes, cost, exit`). - **Mid-run lane replies (`Claude #3`, `Sol #6`, `Argon Theme 9`):** `P438a` and `P438b` add the global `laneReplies` setting (`next-turn` vs `interrupt`), native agent abort-and-continue, and CLI run stop-and-continue (`--continue-from`). Item 5 below covers what P438 leaves open: delivery acknowledgments (`queued`, `read`, `interrupted`), per-message choice between queueing and interrupting, and native agent `Pause`.
- **Failover worker identity (`Sol #9`):** `P439` makes a failover backup message as `lane:BACKUP` while keeping the primary's inbox replies. Item 2 below covers the remaining UI visibility: showing the failover chain, backup model and reason in Reviews and Inspector.
- **Outside-project writes (`Claude #11`, `Argon #10`):** `P440` adds `external_directory: deny` to non-Bypass `OPENCODE_CONFIG` and updates mode lines in `src/control/modes.js`. Item 1 below covers the remaining gap in `scripts/acp-run.mjs` and adds the per-lane sandbox line in `Inspector.jsx`.
