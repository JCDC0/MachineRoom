# Task briefs

Several agents work on MachineRoom at the same time. Each one works on its own branch in its own git worktree, and Claude reviews and merges every branch. The rules every agent follows are in `docs/agents/HOUSE-RULES.md`. Who works where, on which model, and which paths each agent may not touch are in `docs/agents/lanes.json`. The bridge builds the prompt for a task from those two files and the brief below (`GET /api/control/brief-prompt`, task T1a), so nobody has to write or paste prompts by hand.

A brief is one paragraph that starts `**ID. Title (Owner).**`. Keep that shape: the parser reads it.

## Roadmap: subagents and a public release

The goal is a public application that turns Paperclip into an overview room where you watch agents, and the subagents they start through their own harnesses, move between folders and touch files. The recordings so far hold no real subagent events, so the data comes first.

**S1. Record subagent runs (OpenCode, extends B5).** One scenario per harness, tiny tasks, cheapest model that works: Claude Code starting a subagent with its Task tool, OpenCode starting one with its `task` tool, Hermes using `delegate_task`. Also record Paperclip's own delegation: the Orchestrator agent creating an issue for another agent (the `activity.logged` frame with `issue.created` carries the creator, the assignee and `parentId`). Report which signal in the raw log identifies the parent, the child and the child's tool calls. AGY's own session log for C3a shows it starting a subagent (a "Delegation" routine that invoked one named DeepCoder), so add one headless `agy --print --output-format stream-json` run with a task that makes it delegate, and report whether the stream carries the child.

**S1a. Subagent signals from the Hermes and OpenCode CLIs (orchestrator, done on 2026-10-21).** Recorded by the orchestrator with one read-only task each that asked for one subagent, run in the lane worktrees, a few cents in all. Claude Code, agy and Paperclip's own delegation (`issue.created` with `parentId`) were not recorded. Hermes (`hermes chat -q` with the `delegation` toolset, the stdout Paperclip shows): `┊ 🔀 preparing delegate_task…` when the call starts, then `┊ 🔀 delegate  1x: GOAL...  14.4s` when every child has finished (the count of children, the first goal cut short, the duration). The child's own tool lines never reach the parent's stdout; the session export holds one `delegate_task` call with `tasks: [{ goal, ... }]` and the result `{ results: [{ task_index, status, summary }] }`. OpenCode (`opencode run --format json`): the tool is named `subagent`, not `task`. One `tool_use` line arrives when the child is done, with `input: { agent, description, prompt }`, `state.status`, `state.time.start` and `end` in ms, and `state.metadata.sessionID` naming the child's own session; the child's tool calls are not in the parent's stream. Today's parsers already read both lines as one `other` tool call timed from its duration (`delegate 1x: ...` and `subagent {...}`), and the unreadable counter counts neither. So a log names a child only after it has ended and never shows what it did: S2a, S3a and S2b are held until a harness that streams the child's calls is recorded (Claude Code's Task tool is the likely one).

When the dist folder has no `index.html` it prints `Build the viewer first with npm run build.` and exits 1. ## Roadmap: the assistant and the cost board

**A1. Intent rules and action list (Claude, done as 0.1.20).** `src/assistant/actions.js`, `intent.js` and `llm.js` with `tests/assistant.test.js`. Pure code, no DOM. `interpret(text, context)` returns `{ kind: action | propose | ask | unknown | blocked, action?, say, options? }` where `context` is `{ agents: [{ key, name }], paths: [...] }`. The only way to run an action is `validateAction`.

**A2. Floating assistant terminal (AGY, merged as 0.1.28).** A React component `Assistant` for the HUD, in the style of the wall terminals. Props: `context` (as above), `onAction(action)`, and `ask(text)` (optional, async, returns the same result shape as `interpret`, used for the model fallback). It takes no key prop on purpose. Behaviour: opens with `/`, closes with Escape, draggable, remembers its position in `machineroom.settings`, history with the up arrow. Calls `interpret` on enter. For `action`, show the `say` line and call `onAction`. For `propose`, show a card with the `say` text and two buttons, and call `onAction` only on confirm. For `ask`, show the `options` as buttons that send the option's `text` back through `interpret`. For `blocked`, show the `say` line and open the masked key field if the result carries an `open_config` action with section `keys`. For `unknown`, call `ask` when given, otherwise show the help line. Never echo or store typed text that `containsSecret` flags. Use the mock for any data. Do not edit `src/engine` or `src/assistant`. Add a short test for any pure helper you write.

**A3. Dispatcher (Claude, built as 0.1.31).** `src/assistant/dispatch.js` maps each validated action to the room, the HUD and the control client: camera focus on an agent or folder, wall terminal focus, follow modes, panel tabs, issue and config views, replay controls, and the three confirmed writes through `client.createIssue`, `client.setAgentBudget` and the subagent setting.

**A4. Model fallback route (OpenCode, merged as 0.1.34; the viewer does not call it yet, because it needs a setting that turns it on).** `POST /api/assistant` in the bridge, local pages only. Body `{ prompt }` with a length limit of 2000 characters. It runs `opencode run -m <model> --format json` with a timeout of 8 seconds and returns the model text. The model id comes from an env variable or the settings file and defaults to `opencode/deepseek-v4.1-flash-free`. When no model is set, answer `404` with a plain message. Never log the prompt. Test it with a fake runner.

**A5. Cost board in the room (Claude).** A CSS3D panel floating near the core, fed by `client.costs()`. Per-agent spend and tokens, company budget, quota windows, and "not reported" for a harness that gives no numbers. Click an agent row to fly there. Also a plain HUD version for narrow windows.

**A6. Key form and Paperclip secrets (AGY for the form, OpenCode for the bridge route).** A masked field per agent that sends the value only to a bridge route, which writes it to Paperclip's secrets and never returns or logs it. Needs C2. Check `PAPERCLIP-API.md` for the secrets routes first.
