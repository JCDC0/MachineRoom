# Task briefs

Several agents work on MachineRoom at the same time. Each one works on its own branch in its own git worktree, and Claude reviews and merges every branch. The rules every agent follows are in `docs/agents/HOUSE-RULES.md`. Who works where, on which model, and which paths each agent may not touch are in `docs/agents/lanes.json`. The bridge builds the prompt for a task from those two files and the brief below (`GET /api/control/brief-prompt`, task T1a), so nobody has to write or paste prompts by hand.

A brief is one paragraph that starts `**ID. Title (Owner).**`. Keep that shape: the parser reads it.

## Roadmap: the assistant and the cost board

The design is in `docs/agents/CONTROL-PLANE.md` under "The assistant and the cost board". The rule engine, the action list and the model reply parser exist and are tested.

**A1. Intent rules and action list (Claude, done as 0.1.20).** `src/assistant/actions.js`, `intent.js` and `llm.js` with `tests/assistant.test.js`. Pure code, no DOM. `interpret(text, context)` returns `{ kind: action | propose | ask | unknown | blocked, action?, say, options? }` where `context` is `{ agents: [{ key, name }], paths: [...] }`. The only way to run an action is `validateAction`.

**A2. Floating assistant terminal (AGY, merged as 0.1.28).** A React component `Assistant` for the HUD, in the style of the wall terminals. Props: `context` (as above), `onAction(action)`, and `ask(text)` (optional, async, returns the same result shape as `interpret`, used for the model fallback). It takes no key prop on purpose. Behaviour: opens with `/`, closes with Escape, draggable, remembers its position in `machineroom.settings`, history with the up arrow. Calls `interpret` on enter. For `action`, show the `say` line and call `onAction`. For `propose`, show a card with the `say` text and two buttons, and call `onAction` only on confirm. For `ask`, show the `options` as buttons that send the option's `text` back through `interpret`. For `blocked`, show the `say` line and open the masked key field if the result carries an `open_config` action with section `keys`. For `unknown`, call `ask` when given, otherwise show the help line. Never echo or store typed text that `containsSecret` flags. Use the mock for any data. Do not edit `src/engine` or `src/assistant`. Add a short test for any pure helper you write.

**A3. Dispatcher (Claude, built as 0.1.31).** `src/assistant/dispatch.js` maps each validated action to the room, the HUD and the control client: camera focus on an agent or folder, wall terminal focus, follow modes, panel tabs, issue and config views, replay controls, and the three confirmed writes through `client.createIssue`, `client.setAgentBudget` and the subagent setting.

**A4. Model fallback route (OpenCode, merged as 0.1.34; the viewer does not call it yet, because it needs a setting that turns it on).** `POST /api/assistant` in the bridge, local pages only. Write a pure function `planCollapse({ folders, fileCounts, hot, maxTiles })` in `src/model/collapse.js`. `folders` is a list of folder paths relative to the project root (`''` is the root, then `'src'`, `'src/model'`), in any order; add every missing ancestor before you start, so `['src/model']` alone is the tree `''`, `'src'`, `'src/model'`. `fileCounts` is a `Map` from folder path to the number of files directly in that folder (a missing entry means 0). `hot` is a list of folder paths that must stay open, because an agent has touched them; a hot path that is not in the tree is ignored. `maxTiles` defaults to 400. Open a folder only when the tile count after opening it stays within the budget (it stops being a collapsed tile and each of its children becomes one). When the whole tree fits, every folder is open and `collapsed` is empty. The same input in any order gives the same output. Tests in `tests/collapse.test.js`: a small tree that fits comes back whole; a tree over the budget opens the shallow folders first and collapses the deeper ones with the right counts; a hot folder deep in the tree stays open with its whole chain; the output does not depend on the input order; a hot set too large for the budget gives `overBudget: true` with all of it open; a missing parent is added; and 10,000 folders finish in under 200 ms (time it with `performance.now()` and keep the bound loose so CI on a slow machine passes).
