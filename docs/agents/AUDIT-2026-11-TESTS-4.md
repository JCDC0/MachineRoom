# Test audit 4, November 2026

## Method

The baseline is `acea70f0`. I read the first-parent merges in `4ca6ba63^..HEAD` and took each P556 to P605 merge's diff against its first parent. The range also contains P606, P607 and P609. Their changes are in the baseline, outside the set of hunks to undo. I left out direct commits and lane-internal merges.

I used zero-context diffs. I skipped hunks made up only of imports, comments, whitespace or punctuation. I chose up to eight hunks per brief, starting with the largest eligible hunk in each changed code file, then taking the largest remaining hunks. CSS was eligible when a brief also changed non-CSS code. Helpers under `tests/helpers/` count as code. Changes to assertions alone give this method no source hunk to undo.

I mapped each chosen hunk onto HEAD using the later diff. An undo had to match the current lines exactly. A deletion had to retain both adjacent lines at the same seam. I undid one hunk at a time in a scratch copy, ran the current versions of the test files changed by that merge, and restored the original file bytes before the next run. This replaces `git checkout` because the lane's Git metadata is read-only. The worktree's tracked source was untouched.

I recorded a green undo when Vitest returned zero with the same number of passing tests as the matching baseline. A named assertion failure shows what a test caught. A transform, missing name or runtime error only shows that the undo broke the test path. A later edit that prevented a clean undo is marked stale. Some green hunks are equivalent rewrites or the deletion half of a move. Their rows explain why an extra assertion may add little.

I used up to two Vitest workers per run. The first combined baseline hit the time limit. I split the tests into smaller batches and wrote the JSON report to an explicit scratch path so the runner could read it. A server retry used a scratch Git directory with an unborn `main` to let the cache test exercise its `.git` case. That test passed there. No Git command wrote to the lane's Git metadata.

## Scope and limits

- The table uses line numbers in each merge's result. For a deletion the line is the seam where the old code was restored. Later edits can move the same hunk in HEAD.
- Only the selected hunks and the named brief files were tested. Smaller hunks, new coverage added later in other files, combined undos, the full suite and the browser are outside this check.
- P568 and P576 changed CSS and its tests. I skipped both. P571 to P573 changed direct test cases only, so there was no code or helper to reverse. P558, P564, P575, P579, P582 to P587, P593 and P604 changed docs only. P557, P600 and P601 had no matching first-parent merge.
- I excluded the live lane-send, interrupt and stop groups, the process-tree tests that use real OS processes, the live leftover and reused-process tests, and the bridge shutdown case that kills its runner. The named exclusions in the brief for the orchestrators, ACP log and pack tests were outside the selected files.
- The UI baseline also excluded the stop-reason test that timed out and the three direct-lane worktree cases that started a runner and failed on the scratch baseline. Those exclusions affect the corresponding green comparisons.
- The server retry selected the briefs routes and the attention response in `tests/bridge-routes.test.js`, the request timeout group in `tests/mr-agent.test.js`, and the review confirmation case in `tests/project-reviews.test.js`. It selected `commandFor` and the continuation group in `tests/run-lane.test.js`. All five continuation process cases were red on the baseline and were left out of the comparisons. The passing command tests cannot prove Claude session resumption end to end.
- The first server retry selected two `describe` blocks in `tests/attention.test.js`. This missed direct tests declared outside the blocks, including the brief order and dismiss assertions. I repeated P556, P565, P570, P588 and P594 with all non-process attention tests. The later run supplies their results below.
- I also repeated the two green P580 request hunks with the 401, terminal 502 and malformed-body cases in `tests/mr-agent.test.js`. Those seven cases passed before each undo and after it.
