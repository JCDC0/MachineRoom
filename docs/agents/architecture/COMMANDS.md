# Commands

Every command, with its flags and what it prints.

## Commands

```

It checks git (a warning only when the folder is not a git repository), the built viewer, the runs folder and the lane programs, then reads the project once with the same reader `/api/tree` uses, under a 10 second limit. A lane on the codex harness with a bare `codex` bin starts from the Codex app's newest program in `%LOCALAPPDATA%\OpenAI\Codex\bin\HASH\codex.exe` when codex is not on PATH (P311). Its output puts the file-count line just after the project-folder line, with `ok The project holds 3 files in 2 folders.` or `FAIL The project could not be read: SENTENCE.` without a path. It prints every path it names with its temp, app data, profile or home label in place of the full path, prints the next step to fill the room and then All checks passed, N warning or warnings. when every check passes (All checks passed. with none), and exits 1 on any failure; a failed project folder stops the checks there, so its one FAIL line is the last thing printed; npm run serve -- up runs those checks, hands the bridge the file list the doctor read so the project is listed once (`initialTree`), stops with exit 1 when the project folder does not exist, prints All checks passed. when every check passes, then a block with the process id, the port and the address, how the room fills and how to stop it, opens the browser with --open, and serves the room with the lane and session sources on whether they passed or not
machineroom [FOLDER] [--no-open] [options]   after npm link in this folder, from any project folder: machine-room up --root on that folder (the current one by default) with --open unless --no-open is given, printing the process id, the port and the address; --help prints Usage: machineroom [FOLDER] [options] (bin/machineroom.mjs, upArgs in server/doctor.js)

npm run scale-live -- [--files 200000] [--folders 20000] [--seed N] [--keep] [--tree-only] [--server FOLDER] [--quiet-ms N]   build a seeded git checkout under %TEMP%\machineroom-scale\FILES-SEED (reused when it matches, refused under 2 GB free, removed at the end unless --keep), start the bridge on it in a child process, and time the first tree read, the gzip folder answer, the bridge's memory, a new file reaching a page, and bursts of 2000 files into an untracked folder and a gitignored one (the bridge's own CPU share; git's is not counted), then the doctor's project read, `GET /api/git` clean, with 2000 untracked files and with 1000 changed files, a lane worktree made and reused, the reviews list and a lane diff with one commit ahead, and a read of the folder with its `.git` set aside; it prints the free space first and each row as it is measured; a dev tool left out of the pack `--tree-only` times only the tree path, `--server FOLDER` runs the bridge of another checkout on the same seeded tree, and `--quiet-ms N` measures the bridge for N milliseconds after the new file (0 by default; `AUDIT-2026-11-TREE-COST.md` used 120000); --help or -h prints `Usage: npm run scale-live -- [--files N] [--folders N] [--seed N] [--quiet-ms N] [--server FOLDER] [--tree-only] [--keep]` and exits 0 before it builds a tree
npm run scale-probe -- [--files 40000] [--folders 4000] [--seed N] [--replay]   time each stage of the room on a seeded tree in memory (readTree with a fake listDir, the tree event, makeTree, the state, planFolderView, layoutRing, the Hermes pipeline) against 16 ms for work per frame or activity, 1 second at load and 2 MB for a tree event; --replay prints a digest of the activities, folder plans and layouts of each fixture and each public/recordings/*-run.jsonl, to diff two versions; --help or -h prints `Usage: npm run scale-probe -- [--files N] [--folders N] [--seed N] [--replay]` and exits 0 before it times a stage
npm run screenshots -- [--port 5180] [--out docs/images]   take the five room screenshots from a built room that `npm run serve` already serves: start the Playwright Chromium on this machine headless with SwiftShader, set the guide flag before each load, drive the replay with the range input and the F, 0 and C keys, wait for each view, and write overview.png, closeup.png, drawer.png, connect.png and scale.png under the output folder, each under 400 KB; a dev tool left out of the pack; --help or -h prints `Usage: npm run screenshots -- [--port 5180] [--out docs/images]` and exits 0 before the room check
npm run decide-eval -- [--run|--smoke] [--models a,b] [--set NAME] [--repeat N] [--limit N] [--llm ID] [--url URL] [--llm-url URL] [--key-env NAME] [--json PATH]   compare decision models on the probe sets: prints the plan and estimated cost with no call, --smoke makes one call to check the key, --run runs the comparison (see DECIDER-EVAL.md; the key comes from OPENROUTER_API_KEY or --key-env)
npm run run-lane -- opencode T2   start one lane on a brief, add --dry-run to print the command and the line `Dry run, nothing started.`, --help or -h, where an option is expected, prints a usage block with the forms, the common flags and a lane from the lane file in use (a bare run with no lane prints the same block on stderr and exits 1), --list prints the last 10 run records (a record with failover adds `| moved to LANE (KIND)` and one with failoverFrom adds `| taken over from LANE`; with no runs it names the masked runs folder and how to start one), a lane name the file does not hold stops with `There is no lane named LANE.`, the lanes the lane file holds, its path (masked only under a known root) and the room's Agents tab, --stats (with --since YYYY-MM-DD) prints runs, minutes and cost per lane and model (with no runs it prints `No runs recorded.`), --outcomes (with --since) prints the merge table (with no runs it prints `No runs yet.`), --model and --reasoning change the model for that run only (the fleet's `agy`, `agy2` and `agy3` lanes run Gemini 4 Hydrogen, `agy` and `agy2` at XHigh and `agy3` at High), --minutes N sets the time limit (100 by default), and --stop LANE stops that lane's run, its harness and every process still working in its worktree, reads the lock again after it stops the run's own processes and before the worktree leftover search, so a newer run that took the lock keeps its processes and its lock, prints what it stopped and removes the lock only when every live target stopped and no newer run took the lock meanwhile, otherwise it keeps the lock and says why; a lane lock carries the run's start time and `--stop LANE --started-at ISO` reads the lock just before it kills anything and refuses with `The LANE lane is running a different run now, so nothing was stopped.` and exit 1 when the lock's start time is missing or differs, while a stop without --started-at behaves as before, and the bridge passes the confirmed start time to both a start and a stop; a project run's lock names its project folder, which the stop uses instead of a lane worktree, and the stop matches processes by name only outside a project run; a new run refuses a live harness child or worktree leftover, counts a Windows child that started after the lock file as stale, and names `--stop`; a brief runs in this repository only, so the bridge refuses a brief run on a room rooted in another repository with `Briefs run in this repository. Use a task or a queue on another project.`; --project FOLDER with --task TEXT or --task-file PATH runs the lane in that folder instead of on a brief, and it refuses this checkout, a lane worktree from lanes.json and a git folder with uncommitted changes unless --allow-dirty, makes no branch and writes no recording, and holds `<runs>/project-<hash>.lock` (the hash of the resolved folder) with its pid for every --project run, so a second run on that project stops with one sentence; --test COMMAND is one check after a single project task or queue task and may be given up to four times, the runner runs them in order in the run's folder and stops at the first that fails, so a task passes only when every check passes, the log and the summary name each command `passed` or `failed`, and with no --test it runs npm test when its package.json has a test script; the check splits on whitespace, double quotes group words, `\"` is a literal double quote inside or outside quotes, `\\` is one backslash and a backslash before any other character stays, an unclosed quote is refused before the run with `The check command has an unclosed quote.`, the room's saved setting holds up to 4 non-empty lines, one command per line, and refuses a fifth with `A check holds at most 4 commands, one per line.`, each line takes the same check and the bridge passes one --test per line, and a Dispatch start refuses the same commands, npm and npx on Windows start through Node and npm's own JavaScript entry point, and a command holding `|`, `&`, `;`, `<`, `>`, a backtick, `$(` or `%NAME%` is refused before the run with `The check command cannot use shell syntax; put it in an npm script.`; --worktree with --project runs it in `<project>/.worktrees/<lane>` (with `/.worktrees/` added to the project's `.git/info/exclude`, and the bridge's file tree and watcher skipping `.worktrees`), a git worktree made from HEAD when missing, reused when clean and refused when dirty or when it is on a named branch with commits the project's HEAD does not have (`The LANE worktree is on BRANCH with N commits not in the project yet. Merge or remove it first.`), while a detached worktree keeps its own commit check, with a node_modules link to the project's own, locks that worktree folder instead of the project so lanes in their own worktrees run side by side, and a queue with --worktree makes its branch there, while --dry-run prints the worktree path and whether it would be made; it refuses, before anything starts, a brief that is missing, repeated, marked merged, owned by another lane or whose branch already exists, and a lane marked retired in lanes.json (--force skips the merged, owner and retired checks). A Claude Code run's cost comes from its last `result` line, so it is what the API would charge, not what a subscription bills; the record also carries `inputTokens` and `outputTokens` when the harness reports them. It carries `peakTokens` too, the largest context one step of a Claude Code or OpenCode run held (input plus both cache counts), and `--list` prints it as `peak N` while `--stats` prints each lane's `peak median N, max N, K at or over 450,000` (P32). Every record carries `base`, the HEAD the worktree or queue branch was made from, so the scope check can diff the lane from where it started, and a project run's `.meta.json` carries it beside the lane, the project and the session id. When started inside Claude Code or OpenCode without `--started-by`, run-lane records that session (from `CLAUDE_CODE_SESSION_ID` or `OPENCODE_SESSION_ID`) in `startedBy` in the run record and its `.meta.json`. In a project run the record names the folder's branch when it is not the branch the run started on, and lists `git log --oneline START..HEAD` in the folder the run worked in, where START is the head read before the harness started; a queue task's record waits for its commit, so its `commits` names the commit the room reports. Every queue task's record carries `queueSize`, and the record where the queue stops carries `queueRemaining`, the masked text of each task after it cut to 200 characters (P223). `--queue FILE` runs the tasks in a plain text queue on that project instead of one task, separated by lines that hold only `---`, 1 to 4000 characters each and at most 20; the project must be a git checkout and clean, and the bridge refuses a queue or a `worktree: true` run on a folder that is not a git checkout before it writes anything, with the sentence the runner would print; the runner makes and switches to `machineroom/queue-<lane>-<stamp>` from its HEAD before the first task, runs the `--test` text or `npm test` when its package.json has a test script after each task without a shell through the same check, fails the task when an existing package.json cannot be read or parsed, keeps a task's own commits on the queue branch when it made any and left the tree clean, recording the newest sha, and otherwise commits what it left with its first line as the subject, the queue's body and a `Co-Authored-By: LABEL (MODEL) <ADDRESS>` trailer for the lane's harness (no `MODEL` when it is unknown, and no trailer for a harness without `commitAuthor`), notes a task with no change, stops at the first failed task or test with that task's changes left uncommitted, records `queueStatus: failed` for a failed harness and `stopped` for a kill with `queueRemaining`, prints the branch and one line per task, leaves the project on the queue branch (`git switch -` goes back), and never pushes. When MCP servers are enabled in Settings (`<runs>/mcp.json`), Claude Code and OpenCode runs receive `<runs>/<log name>.mcp.json` written with mode 0o600, passed as `--mcp-config` or `OPENCODE_CONFIG`, honours the returned env, and removes the file when the run ends; `--dry-run` prints the config path and enabled server names without env values (H16). OpenCode runs pass `--standalone` so their private server stops with the process tree (H18). A run that fails in its first minute with no tool call prints `start failed:` with the harness's error, or with the spawn error when the program did not start, and records `startFailed`; a program that cannot start counts as a failed start and moves to the backup lane, and one that made no commit with the readiness sentence in its log records `retried: true` and runs once more as `<log name>-retry` (S27, S32). The runner makes the runs folder again when it was deleted during a run, prints that it made it again with the path masked, and still writes its record; the log, record and recovery lines it prints mask the longest matching prefix of `%TEMP%`, `%LOCALAPPDATA%`, `%APPDATA%`, `%USERPROFILE%`, `$XDG_STATE_HOME` and `~`, a dry run masks the program, the arguments, the working folder and the MCP config the same way, and a refused project lock masks both the project and lock file paths. Queue dry runs mask the project path, and worktree dry runs mask the worktree path (P123, P140, P144). `MR_AGENT_MAX_COST_USD` stops the native agent before its next request once its counted cost reaches the limit, and when an answer reports no dollar cost, a 200 answer is damaged, or the request is lost with no answer, it stops before any retry with `The cost limit is set but the provider did not report a cost; stopped.`; every stop prints its sentence and exits 3, and the limit reaches only a machineroom lane (P89, P104, P117, P121). A lane may name `fallback`, another lane's key: when a brief run, a single project task or a queue task ends with a non-zero exit, prints a quota, rate limit or overload error, or fails to start, the runner writes `failover: { kind, to }` on that record, prints `moving the run to LANE because KIND`, and starts the same briefs or task once on the backup lane on a branch ending `-on-LANE`, with `failoverFrom` on the second record; a failover never moves again and a killed run never moves, a backup whose lock is held prints `The backup lane LANE is busy, so the run stays failed.`, a backup lane passes the same worktree check as a starting lane, so a backup whose worktree is the main checkout or another lane's leaves the run failed, and a fallback that is unknown, retired, the lane itself or the orchestrator stops at start with one sentence. A queue is not left alone either: its failed task moves to the backup lane on a branch ending `-on-LANE`, the queue goes on there, and its summary names the branch the backup used. The native agent retries an API answer whose body is not JSON or lacks choices, such as a 502, up to 4 times, and reports the HTTP status and the start of the body after the last try. A native agent's empty or reasoning-only reply gets one nudge, and a second one ends the run with exit 1 and `The agent stopped without a final answer.` A machineroom lane's run log becomes a recording, so native runs replay like the others. A lane with `cli.commits` set to `runner`, such as the codex lane, has only the paths its briefs' Files lists name put on the brief's branch and committed by the runner after a run that ends with exit code 0; every other changed path is left out and printed as `Left out of the commit: PATH`, a path under `dist`, `build` or `out`, a log, a key file or `.env` is always left out, and a run of several briefs takes every brief's list (P75, P116). A brief's body is every line from its heading down to the next heading, so its Files list and the paragraphs after it stay with the brief (P116), and a Files list ends at its first blank line, so a path in the next paragraph is not taken, and the last `Files:` marker outside code wins. Markers inside matched inline backticks or closed code fences of three or more backticks or tildes are ignored. Prose quotes and apostrophes do not hide a marker (P121, P133, P143).
npm run hand-run -- LANE ID --minutes 40   record a run started by hand in runs.jsonl with source hand, from the lane worktree's branch (--minutes, --branch, --model, --exit), so npm run outcome accepts its branch; it refuses a lane with a command line, a brief briefProblems refuses and a branch that has a record; every lane in lanes.json has a command line now, so it refuses them all; --help or -h prints `Usage: npm run hand-run -- LANE ID [--minutes N] [--branch NAME] [--model NAME] [--exit N]` and exits 0
```
