# Audit of the orchestrator and the worktree runs, version 6

Written 2026-10-24 by OpenCode 6 on the branch `feat/r6-audit-of-the`, from `1144d1f` (0.1.255) to `66bd85f` (0.1.276), for brief R6. That is 40 commits, 43 files, 3195 lines added and 5311 removed in `src/`, `server/`, `scripts/` and `bin/` (`git diff --stat 1144d1f 66bd85f -- src server scripts bin`), and 116 files, 9118 added and 13152 removed over the whole tree, because Paperclip's removal (Y1, Y1b, Y2, Y3) deleted more than this span added. The brief says 0.1.255 to the newest commit; the base is the 0.1.255 commit, so the span starts at the first commit after it. It reads the orchestrator in the bridge (K1), its chat in the room (K2), worktrees for parallel lanes and the orchestrator's instructions (K3), task queues (S8, S8b), the worktree runs in the lane source (S9), and the fixes made at each merge. File and line numbers are those of `66bd85f`.

The audits before this one are `AUDIT-2026-10.md` (the bridge and the pure logic), `AUDIT-2026-10-UI.md` (the browser), `AUDIT-2026-10-DELTA.md` (0.1.121 to 0.1.152), `AUDIT-2026-10-V4.md` (0.1.201 to 0.1.222) and `AUDIT-2026-10-V5.md` (0.1.228 to 0.1.243, with its fixes in 0.1.248). This review does not repeat their findings. It looks at what this span added: a long-lived Claude Code turn inside the bridge, a chat file that outlives it, a page that can start it, lane runs in worktrees of another project, queues that commit on a branch, and the lane source that shows worktree runs on the room's own paths.

## Severity

- High: a normal load or a normal click shows the room wrong.
- Medium: a normal case, such as a seek, a failed tool call or a folder change, shows wrong output, or a resource grows over a session, with no lasting harm.
- Low: odd input, extra work per frame, or slow growth with no lasting harm.

W1, W5 and W7 can leave a lasting change: a mixed commit in a project, a lane that edits the wrong repository, or a command run from a page on another port. They are Medium because each needs a second run, a brief id that both projects share, or a local page on port 5173, not a normal click.

## What was checked and found sound

- The origin and confirm gates on the message and stop routes: 400 without `confirmed`, 400 outside 1 to 8000 characters, 409 with no project, and stop sets `paused`; the tests cover each. A foreign Origin is 403. A request with no Origin is allowed by design, so the orchestrator's own `curl` works (W7 is about port 5173, not about curl).
- A turn's child does not outlive the bridge on this machine: a Node child spawned without `detached` dies when its parent is force-killed, and the orchestrator spawns it without `detached`. `stop` and the 60 minute timer also call `killTree`, and the stop test passes.
- The wake path: only a `heartbeat.run.status` frame with `succeeded` or `failed` wakes the orchestrator, a frame from its own lane is skipped, a room-started turn is counted against the rolling cap, a message that arrives during a turn waits for the next one, and a paused chat is not woken.
- The prompt and the chat: `turnText` caps at 20000 characters by whole blocks and always keeps one, `restore` caps at 200 messages, and `visibleChatText` hides bidi and control characters on the page. A missing prompt file falls back to the three-sentence prompt, tested.
- The session flags: `--session-id` on the first turn, `--resume` after it, both restored from the file; the test checks the second turn's args.
- The worktree rules: a missing worktree is made from the project's HEAD, one with uncommitted changes is refused, one from another repository is refused, `node_modules` is linked once and left out of the dirty check, and `prepareWorktree` runs inside the lane lock, so a second start of that lane cannot take it.
- Project checks: a project run resolves both sides and refuses this checkout, a folder that holds it, a git checkout of this repository, the user profile, the temp folder, the runs folder and a dirty folder. The run route also refuses the orchestrator lane and a retired lane, and the queue route refuses `allow-dirty`.
- S9 in the lane source: a run whose meta project is a worktree of the room's repository is shown with its worktree path rewritten to the room root, a run on an unrelated folder is skipped, and a run on the room's own root keeps its paths. The orchestrator's own log is read as the lane `orchestrator`, its tool calls appear at the hub centre, and its end frames do not wake it.
- Queue mechanics: the queue holds the lane lock for its whole run and each task runs through `startLane` with no lock of its own; each task's record carries `queue` and `queueIndex`; the test command comes from the project's `package.json`; and a failed task or test stops the queue with its changes uncommitted.
- Lane records, the chat file and the queue files live under `%TEMP%\machineroom-runs`, and the lane frames are masked before the page and the history. The orchestrator's lane is refused by both `run-lane` and the runs route.
- `npm test` and `npm run build` pass on this tree (the counts are below).

## What this session could not check

- A real Claude Code turn or a real lane harness run. The brief forbids starting an agent run. Every proof uses an injected spawn or a fake runner, and no program was started to do work.
- A browser or a screen. W11 and the look of the chat panel are left to the orchestrator.
- The git interleaving of W1 with two real harnesses. The bridge half is proved; the commits are a code read.
- A crash during the state file write. The file was cut by hand, not truncated by a dying process. W3's two-room case and W12's restart loop are code reads.
- A run on ulolTris (W5). The gate is proved on a temp project, and the runner's refusal with the real `run-lane`; the wrong-repo run was not made.
- Whether a harness commits in a detached worktree (W8). The reachability of such a commit is proved in a temp repository.
- A second start of one lane through two bridges. The lane lock covers it and its tests pass, but two real `run-lane` processes were not started.
