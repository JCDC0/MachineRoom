## Merge by merge

- `P44` (`722891c9`): the file tools now match Claude Code's shape. `read_file` reads 2000 numbered lines with `offset` and `limit`, spots a binary file from an 8 KB probe, `search` takes `glob` and `ignore_case` and skips gitignored files, `glob_files` lists by glob, `edit_file` takes `replace_all`, and `run_shell` keeps the first 2,000 and last 6,000 characters, the exit code and a 600 second cap. On Windows `shellFor` picks Git Bash, then a PATH bash, then PowerShell. Findings 1, 5 and 6 come from the new tool code. The link escape predates P44, but `glob_files` and `search` now walk it.
- `P45` (`0e83cf0d`): the system prompt names the working folder, the system, the shell and the date, and carries `AGENTS.md` or `CLAUDE.md` from the working folder only, cut at 20,000 characters. The retry covers 429, 500, 502, 503, 529, network and timeout failures 5 times in all, never a 400 or 401, with 2 to 16 second waits or `retry-after` up to 60. The step limit is 200, `max_tokens` is 32000, `--reasoning` becomes `reasoning: { effort }`, the peak comes from each assistant line's usage, and a `bash.exe` under the Windows folder is refused. The retry wraps only the model call and the tools run after the reply, so no double write. Finding 2.
- `P46` (`91574aa4`): `ringPulse` takes an optional floor, the hub keeps its old 0.32 maximum, and an agent ring now uses 0.8 with a 0.35 floor. The ROOM.md line and the two tests match the code. No finding.
- `P36b` (`9ec6f281`): a watcher event that names a path, at most 50 of them, turns into `git ls-files -- <names>`. The names come after `--`, so a name that starts with `-` is a path and not an option; proved with `-n.txt` and `--help`. A named folder replaces every held path under it, a path the list no longer answers is sent as `removed`, and a partial failure, 51 names, a nameless event or an unarmed watcher falls back to a full read. Every tenth read is full, but only on the next read. Findings 3 and 4.
- `P47` (`5b545666`): `readAllLanes` no longer applies the old global `removed` list. At start the bridge moves that list into this project's `project-lanes-<hash>.json` and empties it, which is idempotent: a second call moved `[]`. A `lanes.json` lane is hidden in this project only and still runs in another project; an owner-made lane is deleted from `agents` for every project. Hidden lanes leave the active choice, the family tree, `/api/agents` and the family mock, and Settings shows them with Show. Finding 7. The other two things the brief asked about did not turn into findings: `run-lane` never reads a hidden list, by design, so a hidden lane still starts MachineRoom's briefs, and the hidden file is keyed by the bridge's own project path.
