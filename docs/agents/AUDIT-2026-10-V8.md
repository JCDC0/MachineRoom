## Severity

- High: a normal load or a normal click shows the room wrong.
- Medium: a normal case, such as a seek, a failed tool call or a folder change, shows wrong output, or a resource grows over a session, with no lasting harm.
- Low: odd input, extra work per frame, or slow growth with no lasting harm.

No finding is High. Nothing here shows the room wrong on a normal load with no set-up. W1 is Medium because a click on a folder card followed by an arrow key, a scrub or a Space at the end of a replay leaves the camera 700 units from a card that is gone, and the room stops refitting until the owner parks. W2 is Low because the fit is late, not wrong, and the sound reference distance is stale until the next park. W3 is Low because the wheel and the Zoom rail do nothing while a card is held and the rail's handle snaps back, with Escape and the `0` key as the way out. W4 is Low because a focus on an agent the room has no view for leaves the camera on the last agent while the marker clears, and it needs a roster that disagrees with the caller's list. W5 is Low because a long folder name leaves a strip of the card uncovered by the depth blocker, which is a seam and not an interaction.

## What was checked and found sound

- The hold does not survive a new project or a mode switch between Live and Replay. Only `source.status === 'ready'` renders `Stage` (`src/App.jsx:186-189`); a switch sets the source to loading and unmounts it, and the room's effect disposes the old room when `data`, `agents` or `player` changes (`src/Stage.jsx:351-414`). A project pick calls `openProject` and reloads the page (`src/ui/Launcher.jsx`). So those paths make a new room, not a stale one. A resize does not need to end a hold: the held card's position is in world space and does not depend on the lens. W2 is the fit, not the hold.
- `backOffsets` is a single 270 degree line and both the paint and the blocker use it. Back 0 is the face at the origin, each later back is one `BACK_STEP` (12) further along negative x with no y, and `backPlaces` drops the face and keeps at most three, so the pile reaches at most 36 pixels left of the face and never grows downwards. A step that is not a positive finite number falls back to `BACK_STEP`, and a negative or missing count gives the face alone. `paintBacks` writes the same offsets as `translate3d(x, 0, -6 * (index + 1))` and `occluderParts` adds a face and a tab part for each, so the paint and the blocker agree on the offsets. The tests at `tests/cards.test.js:184-229` cover the counts 0, 1 and 3, a 20 pixel step, one line, and the three `is-back-N` elements with their transforms; the probe's 24-`W` card confirmed the blocker's face part is 248 wide, which is W5's gap.
- `backCount` cannot hide a repaint. The paint depends only on `backLayers(view.back)` through `backPlaces`, which is exactly the number `paintBacks` stores, so the same key means the same children; `view.back` is the count of undrawn child folders, which are exactly the dir rows of that card, so a change in `back` always comes with a changed row list, and the plan recomputes on any change of files, focus or spray. `card.backs` is touched only by `makeCard` (empty) and `paintBacks`, so the cache cannot go stale. A code read of `src/engine/cards.js:192-209`, `:221`, `:490-501`, `src/model/folderView.js:233-240` and the plan keys in `recompute`.
- The pile cannot cover the name row or the file rows. Each back is a child of `.mr-card` with `inset: 0` and a translate on x and negative z only, the face is `position: relative; z-index: 1`, the back's tab is at `top: -9px`, above the card's top edge, and the name starts 8 pixels below the head's top. The pile only overhangs to the left and always behind the face. The one strip that is not covered by the stack is W5, and that is a gap in the blocker, not a cover. A code read of `src/styles.css:4981-5182` and `src/engine/cards.js:391-396`, `:490-501`. The eye check at 1280 by 800 is left to the orchestrator.
- The wheel behaves as the changelog says. Over the items of a scrolling list, the listener in `makeCard` (`src/engine/cards.js:406-412`) stops the event, so the list scrolls natively and neither the page nor the camera moves. Over the head or the face of a scrolling card, `onCardWheel` (`src/engine/room.js:292-301`) prevents the default and scrolls the list. Over a card with nothing to scroll it returns, and the lens wheel handler (`src/engine/camera.js:193-197`) zooms the camera. No path scrolls the page. The room's scroll path is reached only for the face and the head because the items listener stops the wheel first, which is consistent, not dead code. A code read; `stopPropagation` is allowed in a passive listener.
- A double click that anchors a card cannot also park. `onCardClick` is a capture listener on the CSS3D renderer's element (`src/engine/room.js:290`), so it runs only for a target inside a card, a chip or a callout; a click on empty lens space targets the CSS layer div, which is outside that element, so no anchor runs. `onEmptyDoubleClick` (`src/Stage.jsx:710-714`) returns for a target inside `.mr-card`, `.mr-term`, `.mr-term-console` or `.mr-board` and for an agent hit, so a double click that anchored a card cannot reach `parkRoom`. A double click on empty space parks without anchoring. A code read of `src/engine/room.js:282-290`, `src/Stage.jsx:710-714`, `:798` and the layer rules at `src/styles.css:276-291`. The sequence on screen is left to the orchestrator.
- An anchor on a drawn folder stays in the ring. `planFolderView` draws every ancestor of every drawn folder (the focus ancestors, the pinned breadth-first run from the root, and the children of focus folders), so `nearestDrawnPath(path, drawn)` returns `path` itself for a drawn card, and `anchor` returns false when the card map has nothing drawn. A temporary probe checked six plans: two folders, nine folders, depth 3, a focused deep folder, a sprayed folder, and a focused three-level path. Every non-root drawn path had its parent drawn and `nearestDrawnPath` returned the path. A click on a card that is fading out anchors its nearest live ancestor, which is what the helper is for.
- The keys park like the button. `0` always calls `parkRoom`; Escape does when no panel or dialog is open, and each panel closes itself on the same Escape (`src/ui/Hud.jsx:486-497`); `hudKeyBlocked` keeps both away from inputs and dialogs. `parkRoom` (`src/Stage.jsx:704-708`) sets follow off, calls `room.park` and clears the focused key, and `park` releases the hold, clears the follow and refits. A code read.
- The layout reserves the pile's width on both axes. `cardSize` adds `back * BACK_STEP` to the width and to the height, while the drawn pile grows only to the left. A three-back card therefore reserves 36 units of height it does not use, which makes the ring radius, the overview fit and `cardRadius` slightly larger than the drawing needs. It cannot cause an overlap or a wrong drawing, so it is noted here and not listed as a finding.
