# Review 29: the batch since the last push

Reviewed the 21 first-parent merges in `1bb54a0f..4224921d`, against the code at `c7bad713`. The assumed use is one owner with parallel lanes sharing a runs folder. The review concentrates on writes, process starts, archives and recovery. Findings below include concrete cases confirmed with synthetic data, except the shell execution, which is explicit in the runner.

| # | Location | What goes wrong and when | Smallest fix | Blocks a push? |
| --- | --- | --- | --- | --- |
| 1 | `server/storage.js:482` (P217) | The archive follows junctions in its destination parents. With `<runs>/archive` pointing to another folder, archiving an old log removes it from runs and writes it into that other folder. The checks only inspect the final filename. The same missing parent check affects a junction at the month folder. | Reject junctions and symbolic links in archive parents. Resolve the destination parent and verify it stays under the real runs folder before moving. Use an exclusive destination operation so a concurrent destination cannot be overwritten. | Yes. File moves can escape the archive boundary. |
| 2 | `scripts/run-lane.mjs:614`, reached from `server/runs.js:719` (P224) | The saved check reaches `--test` as one argument, but `runTestCommand` runs that string with `shell: true`. Shell operators and environment substitutions are interpreted. For example, a literal `%VARIABLE%` argument on Windows changes to its environment value. The check therefore does not preserve the owner's typed arguments. | Parse the executable and quoted arguments, refuse shell syntax, and launch with `shell: false`. Resolve npm through its JavaScript entry point on Windows. Keep `target.path` as the working directory. | Yes. The saved-command boundary still invokes a shell. |
| 3 | `server/runs.js:997`, `server/runs.js:495` (P219) | The stop route relies on `readActor`, which accepts a request without Origin when the orchestrator registry is absent. A bridge started without `--lanes` has no registry but still mounts the runs routes. A synthetic bridge accepted both a run start and its stop without Origin or token, returning 202 and 200. | Refuse requests without Origin when no registry can authenticate them. Apply that shared rule to both start and stop. | Yes. A write route bypasses authentication. |
| 4 | `server/runs.js:744`, `src/briefs/run.js:403` (P224) | A single task without its own worktree receives the saved command as `--test`. It goes through `parseRunArgs`, which rejects that flag with `Unknown option --test.` The lane never starts. The same problem affects a direct single-task `--worktree` request before the queue adapter runs. The existing dispatch test uses a fake runner that only records arguments, so it cannot catch this refusal. | Teach the single-task argument parser about `--test` and run the check in the single-task execution path. Add a test that reaches the real runner parser. | Yes. Saving a check breaks supported task starts. |
| 5 | `server/index.js:1222`, `server/index.js:1359` (P230) | A failed full read sets `changed` to false. Polling then rearms the watcher and stops, even if that read also fails. When access or git recovers without another file event, nothing retries. Folder-shaped requests return `lastTree` at any age at line 1613. A synthetic failure left a new file absent and the health error present after the reader recovered. The current recovery test forces another plain GET, unlike the viewer. | Keep a bounded retry scheduled while the last full read has an error or unreadable subtrees. Cancel it after a successful full read and on shutdown. | Yes. A live room can stay stale after a temporary failure. |
| 6 | `scripts/run-lane.mjs:1091`, `src/ui/panels/runs.js:68` (P216, P223) | When the harness exits nonzero or is killed, `finishPending('', true)` saves `queueRemaining` but leaves `queueStatus` unset. `queueRecoveryAvailable` requires a failed or stopped `queueStatus`. A failed task record with exit code 3 and remaining tasks therefore has no Ask for recovery action. Only test failures and exception paths set the needed status. | Set `queueStatus` for harness failures and kills before writing the record. Check this with a real failed queue record passed to `queueRecoveryAvailable`. | Yes. Recovery is missing for ordinary failed queues. |
| 7 | `server/storage.js:497`, `src/ui/StorageSettings.jsx:137` (P217) | Archive confirmation sends only the age and `confirmed`. The server creates a fresh candidate list and moves all of it. If another old file becomes eligible after the displayed preview, that unseen file moves too. A one-file preview followed by a second old log produced a two-file archive. | Send the displayed candidate identities. Revalidate against a fresh safe preview and move only the intersection. | No. The move is reversible, but the confirmed file list is not respected. |
| 8 | `src/briefs/run.js:940`, `src/ui/panels/runs.js:137` (P223, P216) | `maskedQueueTasks` masks keys but retains home paths. Recovery copies these strings into its outgoing message unchanged. The orchestrator masks the message when accepting it, so this is not a demonstrated leak to the model. | Apply the existing profile-path masking policy to stored task text and recovery text, alongside key masking. Cover a runtime-built home path in a regression test. | No. The final orchestrator boundary already masks it. |
