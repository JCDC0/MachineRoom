# Audit, October 2026

Written 2026-10-20 by a one-off senior session on the branch `claude/confident-wright-z9081g`, from 0.1.98 (`f4342cd`). It covers the bridge (`server/**`, `bin/machine-room.mjs`, `scripts/candidate.mjs`, `scripts/outcome.mjs`, `scripts/run-lane.mjs`), the control client (`src/control/**`) and the pure logic in `src/model/**` and `src/policy/**`. It was read as an attacker on the same machine and as a careful reviewer. Every fix has a test that failed before the fix. File and line numbers are those of `f4342cd`.

The tests ran on Linux with Node 24.22.0, as GitHub CI does. Before: 1195 tests, 1191 passed, 3 failed, 1 skipped. After: 1236 tests, 1235 passed, 1 skipped (the crash retry test, which only Windows can run).

## Severity

- **High**: code from an unreviewed lane branch runs as the owner, or a key can leave the machine, without anyone choosing it.
- **Medium**: a review can be misled, a write reaches Paperclip without the checks the rest of the room applies, the bridge stops or hangs, or a number that feeds the routing policy is wrong.
- **Low**: wrong output or a wrong answer on odd input, with no lasting harm.

## Part 0: what changed for Linux

- `tests/assistant-route.test.js` now passes because the code uses `path.win32` (finding 19). Nothing in the test changed.
- `tests/bridge.test.js` "keeps the run going after the request and kills it when the bridge stops" passes because the code now kills the run on Linux (finding 7). `tests/process-tree.test.js` checks the `taskkill` arguments, the group kill and a real grandchild on both systems.
- `tests/run-lane.test.js` "runs the tests again after the crash and keeps the second result" runs only on Windows, with the reason in the skip note: Linux keeps the low 8 bits of an exit code, so 0xC0000409 arrives as 9. The unit tests of `nextTestStep` still cover both crash codes on every system.
