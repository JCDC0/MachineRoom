Written 2026-10-25 by OpenCode on the branch `feat/q9-audit-of-the`, from `66bd85f` (0.1.276) to `85b9917` (0.1.307), for brief Q9. That is 88 commits, 62 files, 5153 lines added and 1739 removed in `src/`, `server/`, `scripts/` and `bin/` (`git diff --stat 66bd85f 85b9917 -- src server scripts bin`), and 126 files, 10336 added and 2412 removed over the whole tree. The suite grew from 2059 tests in 129 files at `66bd85f` (V6's count) to 2283 tests in 141 files at `85b9917`. The branch was cut from `refs/heads/main` at `85b9917`; main moved on to `fcf2e85` (0.1.310) while this was written, and this audit does not cover the commits after `85b9917`. It reads the sub orchestrators (O1 to O3), the lens and dock (I1 to I5), the harness registry (H1 to H3), the project queue and worktree runs (Q6a, R5, R10, W7), and the faster test suite (T1). File and line numbers are those of `85b9917`.

The audits before this one are `AUDIT-2026-10.md` (the bridge and the pure logic), `AUDIT-2026-10-UI.md` (the browser), `AUDIT-2026-10-DELTA.md` (0.1.121 to 0.1.152), `AUDIT-2026-10-V4.md` (0.1.201 to 0.1.222), `AUDIT-2026-10-V5.md` (0.1.228 to 0.1.243) and `AUDIT-2026-10-V6.md` (0.1.255 to 0.1.276). W10 and W11 were fixed by R3 and Q6c, and W1, W5, W6 and W7 by Q6a.

## Severity

- High: a normal load or a normal click shows the room wrong.
- Medium: a normal case, such as a seek, a failed tool call or a folder change, shows wrong output, or a resource grows over a session, with no lasting harm.
- Low: odd input, extra work per frame, or slow growth with no lasting harm.

No finding is High. X6 is the only one a normal live load shows with no set-up: two dock rows read `not reported` on every lane. It is Medium because the rows are information, not the room, and nothing is lost. X7 needs a ladder; it is Medium because a live room with a ladder draws the sub as a lane and the sector above it as empty. X1 is Medium because the owner's scope and restriction can be lifted, but only by the orchestrator itself, which already has full shell access. X2, X3 and X13 are Medium because a normal command or a normal run on another project can silently pass a check or leave worktrees behind, with no lasting harm.

## What was checked and found sound

- The origin and confirm gates on the message, stop and ladder routes: a page Origin is refused as the orchestrator, `confirmed` is required, a foreign Origin is 403, and a served room refuses the Vite origin while a dev bridge still takes it (Q6a). Q13a later stopped a no-Origin request from claiming the owner; the page rule stays and X1 is fixed.
- `readLadder`: it rejects a missing or non-list `subs`, a bad id, a duplicate id, the id `orchestrator`, a lane key as an id, a duplicate lane, more than 5 subs, a scope entry that is not relative, a scope entry with `..`, an absolute path, a drive letter, more than 20 scope entries, and a `restricted` or `setBy` value of the wrong type. The owner is always allowed; the orchestrator is refused when it changes an owner-set scope or restriction, as the 403 in X1 shows.
- The `..` and drive letter cases on the path side: the scope entries with `..`, an absolute path or a drive letter are rejected by `cleanScopeEntry`, and the paths the check receives come from `git diff --name-only`, which are relative and carry no `..`. A hand-written scope cannot use them to widen its reach today. The different-case case is reachable and is X5.
- The sub lifecycle: each turn has a 60 minute timer; `close()` clears it, kills the turn with `killTree` and persists; `stop` does the same and sets `paused`; `createOrchestrators.close()` closes every instance and the main. `run-lane` releases the project and lane locks in `finally`, including when `prepareWorktree` throws.
- The lane source reads a sub's `sub-<id>-chat-*` log as its `sub-<id>` agent, skips a log whose sub was removed, handles an id with dashes, and builds the agent list without reading the disk on every tick (the lane file is already in memory).
- `npm run worktrees` lists a lane worktree's branch or `detached`, its commits ahead, whether it is dirty, whether its commits are merged, and whether its lane lock names a live process. `--clean` leaves a running lane, a locked or prunable worktree, a dirty one and one with unmerged commits, and it never deletes a branch. X13 is the `node_modules` link, not the clean decision.
- The reviews route requires `confirmed`, a full 40-character head, a lane that has not moved and a clean worktree. A room on another project fast-forwards that project's current branch after the checks; the old merge path aborts a conflict and restores the checkout.
- The harness registry: `AGENT_ORDER`, the parser picker, the line readers, the commands, the reports, replies and usage read the registry; `agy` keeps `parserByAdapter: false`; an unknown harness is still refused by the runner and the recording builder. `npm run pack-check` holds the agent docs the room reads at run time.
- The lens and cards: `lensStatus` handles a missing agent list or log, the card name scale keeps names at 11 pixels or more and clears the inline transform at scale 1, and the cost board mounts in `#hud-dock-costs` in the dock. X6 and X13 are the gaps.
- The ladder model: `sectorArcs` gives the same angles for the same input, puts every lane in one sector in roster order, gives the main the rest and leaves a gap at each end; `shapes.js` keeps `isOrchestrator` true only for the main and `isSubOrchestrator` true for a `sub-` key or the flag. X7 is the flag that never arrives.
- The full suite passes with the counts below. The first full run had one load timeout in `tests/run-worktree.test.js`; that file passed alone with 17 tests, and the second full run passed all 2283, so the timeout is load from the other lanes, not this change.

## What this session could not check

- A real sub orchestrator turn or a real lane harness run. The brief forbids starting an agent run. Every proof uses a real bridge with no turn, git, the real `worktrees` script, or the pure helpers; no program was started to do work.
- A browser or a screen. The lens clip, the dock at 1280 by 800 and 900 by 700, and the live placement of a sub in X7 are left to the orchestrator.
- The X12 race with a real killed child and a ladder change. It is a code read.
- A project on a slow or disconnected network drive, where the synchronous `execFileSync` in `branchChanges` can block the bridge for up to its 10 second timeout on a run end. It is not listed as a finding because the block is bounded and no slow drive was tried.
