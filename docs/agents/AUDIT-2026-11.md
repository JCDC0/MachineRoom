## Detailed verification of each finding

### M1. `otherWorktreeBranches` compares worktree roots to `projectRoot` instead of `--show-toplevel` (`server/git.js:116-128, 203, 420`)

In `server/git.js:116-128`:

```js
export function otherWorktreeBranches(folder, text) {
  const held = new Set()
  const blocks = String(text ?? '').split(/\r?\n\r?\n/)
  for (const block of blocks) {
    if (!block.trim()) continue
    const lines = block.split(/\r?\n/)
    const wtLine = lines.find((line) => line.startsWith('worktree '))
    const branchLine = lines.find((line) => line.startsWith('branch refs/heads/'))
    const path = wtLine ? wtLine.slice('worktree '.length).trim() : ''
    const branch = branchLine ? branchLine.slice('branch refs/heads/'.length).trim() : ''
    if (branch && path && !samePath(path, folder)) {
      held.add(branch)
    }
  }
  return held
}
```

Both `computeGitState` (`server/git.js:158, 203`) and `handleSwitch` (`server/git.js:396, 420`) call `otherWorktreeBranches(folder, wtOut)` where `folder = resolve(currentRoot())`. However, `git worktree list --porcelain` always prints the worktree's top-level directory (`git rev-parse --show-toplevel`), not `cwd`. If `projectRoot` is a subfolder inside a git checkout (for example `C:\repo\packages\web`), `isGitWorkTree` (`git rev-parse --is-inside-work-tree`) returns `true`, `wtLine` is `worktree C:/repo`, and `samePath('C:/repo', 'C:\\repo\\packages\\web')` is `false`. The current worktree's own branch is added to `held`, so `GET /api/git` marks it `worktree: true` and `POST /api/git/switch` refuses it with 409 `WORKTREE_HOLDS_BRANCH_PROBLEM`.

### M2. Detached `HEAD` omitted from `commits`, swallowed `git status` errors in `handleSwitch`, and stale in-flight cache writes (`server/git.js:169-177, 228-236, 284-296, 410-428`)

1. **Detached `HEAD` omitted from `commits` (`server/git.js:228-236`)**:
   `computeGitState` checks `if (branches.length > 0 || head)` and runs:
   `['log', '--branches', '--topo-order', '-n201', '--format=%H%x1f%P%x1f%ct%x1f%s%x1e']`.
   Because `--branches` walks only `refs/heads/*` and omits `HEAD`, a checkout detached at a commit that is not an ancestor of a local branch (such as a detached commit ahead of `main`, or a repository with a detached `HEAD` and no `refs/heads/*`) is omitted from `commits`.
2. **`handleSwitch` swallows `git status` failures (`server/git.js:410-418`)**:
   In `handleSwitch`:
   ```js
   let dirty = false
   try {
     const status = await runGit(folder, ['status', '--porcelain'], gitRunner)
     dirty = status.trim().length > 0
   } catch {}
   ```
   When `runGit` rejects (for example on the 4 s timeout `GIT_TIMEOUT_MS` or when `.git/index.lock` exists), `catch {}` leaves `dirty = false` and runs `git switch refs/heads/${branch}` anyway. In addition, `handleSwitch` and `handleBranch` have no in-flight mutex, so two concurrent POST requests can run `git switch` and `git branch` in parallel in the same checkout.
3. **Invalidated in-flight read repopulates `cacheByProject` (`server/git.js:284-296, 343-348`)**:
   When `invalidateCache()` runs (on `POST /api/git/switch`, `POST /api/git/branch`, or a run's terminal `heartbeat.run.status` in `server/index.js:727`) while a `computeGitState` call is already in flight, `cacheByProject.delete(resolve(root))` removes the map entry, but when the older `inflight` promise resolves it executes `cacheByProject.set(folder, { value, at: Date.now(), inflight: null })`, caching the pre-change state for the next 2 seconds (`DEFAULT_TTL_MS`).
